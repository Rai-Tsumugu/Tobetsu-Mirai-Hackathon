# 部品・材料単価マスタ M01〜M30

すべての例示価格・数量・配合・指数は架空値の Simulator です。
専用フォルダだけで動作し、Python 標準ライブラリと SQLite を使用します。
React / FastAPI は設計資料の技術候補であり、依存インストールなしで試せる
独立したローカル実装にしています。

リポジトリのルートで実行:

```sh
PYTHONPATH=src python3 -m auto_repair_items.app --port 8765 --db /tmp/auto_repair_items.sqlite3
```

ブラウザで http://127.0.0.1:8765 を開くと統合ワークスペースを表示します。
確認状況 → 材料・価格登録／CSV候補の承認 → 見積保存 → 実使用量記録を
一つのDBでつなぎます。見積行IDは保存結果から実績入力へ引き継ぎます。
個別30案の画面は `/ideas`、統合APIは `POST /api/workspace` です。
統合処理は `integrated.py`、統合画面は `workspace.html` にあります。
販売価格を確認して見積へ保存し、その後の価格更新で保存済み単価を変更しません。
統合画面の小計は税・端数処理前です。配合・掛率・端数規約などの詳細操作は
「30案の個別機能」から利用できます。DBは上記指定先に永続保存され、再起動後も残ります。
ポートが使用中なら `--port 8766` など別の値を指定してください。

```sh
PYTHONPATH=src python3 -m unittest discover -s src/auto_repair_items/tests -v
```

## 共通契約

全案の公開入口は `run(payload, store)`。HTTPでは
`POST /api/ideas/M01` 〜 `POST /api/ideas/M30` に JSON で入力します。
`GET /api/ideas` は各案の名称・架空入力例を返し、
`GET /api/prices` は内部の価格版台帳を返します。

`items` は `item_id, name, category, unit, unit_price, price_type, source,
updated_at` の8項目。名前は全案 `snake_case`、同じ意味の識別子は
`item_id` / `price_version_id` / `confirmed_by` / `reason` を共有します。
金額・数量はDecimalで計算し、JSON・SQLiteでは精度を保つ十進文字列です。
④へ接続する側もDecimalで読み取り、数値型への暗黙変換を避けてください。
金額の丸めはM29で承認した規約だけを適用します。

`core.py` の `Store` は価格版と内部記録を追記保存します。
明示的な価格区分・仕入先・単位・有効日で確認し、承認済み価格がない、
期限切れ、単位違いなどの場合は `ValidationError` / HTTP 400 で停止します。
期限なしは期限切れと区別し、旧版への自動フォールバックをしません。
候補の取込とマスタ登録を分け、見積価格はM30で保存時点に固定します。

## Simulator と実データの境界

- CSVと固定1シートのXLSXはローカルの実読取に対応します。未確認の行は隔離し、
  人が確認するまでマスタ価格にしません。実際の工場ファイル形式・持込許可は未確認です。
- PDFの明細領域とOCR文字は、架空の読取候補を確認するSimulatorです。
  実PDF抽出・画像認識は未接続で、読取精度を検証したとは扱いません。
- 卸JSONはローカルfixtureの対応付けです。卸API・スクレイピングは実装していません。
  本番接続には提供元・契約・規約の確認が必要です。
- 原料指数は参考表示のみ。個別価格へ自動反映しません。
- 配合・使用量は人が承認した提案値です。実塗装のレシピ・現場標準ではありません。
- 個人情報や原伝票全文は取り込まず、品目に必要な項目だけを保存します。
- このサーバーは127.0.0.1限定の検証用途です。ユーザー認証・本番運用・
  外部5システムの実接続・正式帳票生成は今回の範囲外です。

## Luna チームと二重チェック

30案にそれぞれ実装・チェック1・チェック2の担当を割り当て、同時稼働は
最大3担当で順次処理します。担当と最終状態は `team_manifest.json`、
案別の検査結果は `reviews/` に保存します。親担当は共通保存処理、
HTTP・画面・全案をまたぐ統合確認を担当します。

原設計文書や既存 `src/auto_repair_engine/` は変更しません。
