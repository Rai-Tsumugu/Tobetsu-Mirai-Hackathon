# Cの見積もり・発言仕様

以下は内部の提案仕様。工場の実帳票と単価・計算方法を確認して採用する。

## 条件付き概算

| 項目 | 扱い |
| --- | --- |
| case_alias, work_description | 匿名案件ID、対象作業 |
| part_id, unit_cost_jpy | 部品IDと仕入原価。顧客への販売単価とは別 |
| unit_price_jpy, quantity | 顧客提示用の部品販売単価と数量 |
| labor_hours, labor_rate_jpy_per_hour | 作業時間と工場が確認した時間単価 |
| extra_fees | 明細名・金額・含む／含まないを持つ |
| tax_basis, tax_rate, rounding_rule | 工場が確認した税区分・適用税率・丸め。未定義なら税額を出さない |
| price_as_of, valid_until, exclusions | 単価基準日、有効期限、除外費用・追加作業条件 |
| review_status | draft / reviewed。reviewedにするには確認記録が必要 |

例示：部品販売単価3,000円×2、工賃1.5時間×8,000円、追加費用500円なら税抜小計18,500円。入力で全項目に税率0.10を適用すると指定された場合、税額1,850円、総額20,350円。これは例示条件であり、工場の実際の税・料金方針を決めない。

原価が入力された場合だけ別に原価・粗利を計算する。上の例の3,000円を仕入原価に読み替えない。

出力はline_items、subtotal、tax、total、assumptions、exclusions、review_status。未知単価、税区分混在、負数量、未定義工数は問題の行を表示し、勝手に0や平均単価を埋めない。返品などの負数量が必要なら別の帳票仕様として定義する。

## 会話メモ・教育下書き

入力：utterance_id、speaker_alias、text、recorded_at、許可範囲。既存手順がある場合はprocedure_idと版。

出力の各項目：value、source_utterance_ids、qualifiers、needs_confirmation。金額はamount_jpyのほか、税区分、範囲値、概算／確定の発言、含む・含まない条件を持つ。原発言と訂正履歴を残す。

| 例示の発言 | 期待する扱い |
| --- | --- |
| 「たぶん2万円くらい。部品代は別」 | 概算約20,000円、部品代除外、税区分不明。確定合計にしない |
| 「1万か10万か、聞き取れない」 | 金額不明と候補を保持。補完しない |
| 前の発言「2万円」、後の発言「3万円」だが訂正関係不明 | 両方の発言IDと競合を示し、最終金額を決めない |
| 「診断してから追加費用が決まる」 | 追加費用未確定という条件を保持 |
| 「この作業のトルクは……」で数値なし | 数値を生成しない。確認済み資料・担当者に照合する下書き |

録音取得や外部送信の実装はこの仕様だけで許可されたとみなさない。デモは匿名・例示の入力から始める。

## 出典記録

公開データはsource_id、提供者、実際の取得URL、取得日時、対象年・地域・単位、利用条件、加工、原本SHA256。工場提供データは匿名提供記録、許可範囲、帳票の版、単価基準日を残す。原本に個人情報がある場合はGitに入れず、デモに必要な匿名の入力だけを別に作る。
