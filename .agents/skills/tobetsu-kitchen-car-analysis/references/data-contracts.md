# Bの入力・結合・比較仕様

以下はアプリ内部の提案仕様。AirレジCSVや気象庁CSVの実列名を推測して固定しない。

## 最小入力

| 項目 | 型・単位・意味 |
| --- | --- |
| session_id, location_id | 文字列。営業セッションの一意ID、場所ID |
| business_date, opened_at, closed_at | 営業日とISO日時（+09:00）。営業日切替ルールを記録 |
| sales_jpy, tax_basis | セッション売上と税込／税抜。返品・値引きの扱いを記録 |
| sales_origin | session_totalまたはproduct_rows。重複集計防止に使う |
| status | open / closed / unknown。休業と営業売上0を区別 |
| event_flag, stockout | yes / no / unknown。未記入をnoにしない |
| product_id, quantity_sold | 商品単位で提供された場合のみ。販売単位を保持 |
| lat, lon | 位置が確認できる場合のみ。推測座標は区別 |

位置・営業日時がなければ、確定できる日単位・場所単位まで縮小する。商品別の日合計を営業時間別に推定配分しない。

## 気象と地域情報

- weather：station_id、観測日時／日、temperature_c、precipitation_mm、品質情報、source_id。時間別の営業時間平均・合計を作る場合は使用行と欠測時間を残す。
- station_mapping：location_id、station_id、選択理由、距離、対応要素、適用期間。地点選択は出店地との対応を確認してから行う。
- population：area_codeを文字列とし、基準日・調査年・区画・人数単位を記録。
- traffic：区間ID、調査年、12／24時間区分、車種、方向を記録。営業日ごとの実測値にしない。
- GTFS：停留所、路線、便、運行日、対象日付、時刻。calendar_datesの例外と24時超の時刻を扱い、実人数に置き換えない。

気象をsession_idごとの1組に集約してから結合する。複数観測行との結合で売上を複製しない。結合前後のセッション数と売上合計を照合する。

## 出力

comparison_groups（条件・営業件数・売上／時間・分布）、session_details、join_summary（未結合・品質不良・除外件数と理由）、sources、limitations。平均の定義は総売上／総時間か、セッションごとの比率平均かを表示する。

## 例示での受入確認

| 入力 | 期待結果 |
| --- | --- |
| 同じ場所・同じ税基準で2時間／10,000円、4時間／12,000円 | 各5,000円／時間、3,000円／時間。総額／総時間は22,000／6、比率の単純平均は4,000。別の値として区別 |
| 営業中で売上0 | 有効な0。閉店日とは別 |
| 営業時間0または終了が開始前 | 比率計算から除外し、理由を返す |
| 気象欠測 | 営業行を残し、天候不明。雨0に変換しない |
| 同じsession_idの重複 | 重複理由を確認するまで二重に足さない |
| 1日の2場所に日合計しかない | 場所別売上を捏造せず、日単位まで縮小 |
| 商品3行＋気象24行 | 無条件多対多結合をしない。元の売上合計を維持 |
| 欠品日の販売数 | 需要と同一視せず、欠品を表示 |

例示は実績ではない。予測を実装する場合は時系列の学習・評価区間と、予測時点で使える情報を別途記録する。

## 出典記録

source_id、取得URL、取得日時、対象期間、地域・地点、単位、利用条件、加工、原本SHA256。事業者データは匿名の提供者・許可範囲を記録し、顧客情報を公開資料へ含めない。
