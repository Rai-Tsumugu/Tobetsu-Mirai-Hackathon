# 業務データの分析と検証

入力から出力まで追跡できる処理を設計・実行し、事業者が使える判断材料にする。分析の目的はMVPで改善する作業に合わせる。

## 入力

課題ID、改善する判断、提供されたデータまたは文字起こし、項目の意味、利用条件、期待する出力。データがなければ必要項目と処理設計まで作る。例示データで処理を検証しても、実際の事業者についての分析結果にはしない。

## 共通の手順

1. 元データの出所、期間、単位、欠損、重複、タイムゾーン、税の扱いを確認する。原本を保ち、加工内容と除外件数・理由を記録する。未記入を0とみなさない。
2. 必要な列と結果の定義を決め、まず少量で確認する。金額や数量の集計はコードまたは表計算で再計算可能にし、文章生成だけで計算しない。
3. CSV・Excelなら利用可能な表計算Skillを、接続済みのGoogle Sheetsならその編集Skillを必要に応じて使う。利用できない場合は許可されたローカル処理や設計案を使う。Skillの存在だけでアカウント接続やAPI利用を保証しない。
4. 単位の異なる量、税込・税抜、異なる期間を無条件に合わせない。影響する定義が未確認なら、その結果は条件付きの試算とする。
5. 出力を代表的な少量の入力と照合する。観測事実、計算結果、AIの解釈、提案を分け、限界を記載する。

## A・C：原価、価格、見積もり

- 数量の単位換算をして、材料・部品単価×使用量、作業時間×時間単価などから対象範囲の費用を計算する。固定費など含まない費用を明示する。
- 粗利率は `(売価 - 原価) / 売価`、原価に対する上乗せ率は `(売価 - 原価) / 原価`。同一の税・費用範囲で扱い、混同しない。
- 目標粗利率をmとする売価試算は `原価 / (1 - m)`。`0 <= m < 1` を条件とし、売価0、分母0、未知の単価を扱う場合は計算できない理由を返す。
- 価格は事業者の確認前には提案とし、計算日、参照単価、丸め規則、見積もり条件を残す。電話の概算を正式見積もりや合意済み金額に変換しない。

## B：売上・出店・天候

- 日付だけで結合できるか確認する。出店場所、営業時間、気象観測地点と時間帯の対応を記録する。観測データを取得する場合は公式の出所と利用条件を確認する。
- 売上金額、販売数量、営業1時間当たりの値など、何を比べるか明記する。休業日と売上0を区別し、未結合行を数える。
- 店舗・場所・曜日・商品・営業時間などの違いと、条件別の件数を示す。欠品があれば販売数は需要の全量とは限らない。
- 少量の比較や相関から、天候が原因である、売上を予測できる、最適な仕込み量が分かったと断定しない。仕込み提案には対象条件、根拠となる件数、事業者が確認すべき前提を付ける。
- 予測精度を報告するなら、過去から未来への時間順で評価し、既存の単純な方法と比較する。評価できなければ集計・探索段階と報告する。

## A・C：文字起こしから記録・教育資料

- 利用を認められた文字起こしを扱う。録音や電話連携は別の実装・利用条件として確認する。
- 金額、対象作業、条件、未確定事項、発言者を抽出し、元の発言の該当箇所へ戻れる形にする。不明瞭な数字や主語を補完せず、要確認とする。
- 教育資料は手順、注意点、変更候補を整理し、現場責任者による確認前は下書きとする。現場発言だけで整備の安全性や正式な作業基準を認定しない。

## 成果物と完了条件

データ項目と定義、加工記録、計算式または処理、結果、少量照合の結果、限界、画面へ渡す出力例を返す。入力と結果が追跡でき、計算または抽出の確認状況が分かれば完了。未提供データについては設計・例示検証までの完了とする。

発表へ、実データか例示か、検証した範囲、効果の根拠を渡す。
