# C：自動車整備工場などの業務改善：開発準備

ブランチ：`theme/c-workshop-ops`。共通8スキルに、このテーマの専用スキル1件を追加している。この資料は事前準備で、テーマの採用・事業者の要望・Googleの具体的サービスはまだ確定していない。

## 使うファイル

- [テーマ専用スキル](../../.agents/skills/tobetsu-workshop-ops/SKILL.md)：課題ごとの実装判断・確認・実演。
- [データ仕様](../../.agents/skills/tobetsu-workshop-ops/references/data-contracts.md)：入力・出力・単位・受入例。
- [引用元リスト](data-sources.md)：公開ページ、取得方法、期間、地域粒度、利用条件。
- [出典台帳のJSON版](source-register.json)：出典IDと確認状態。実データそのものではない。

## 開発を始めるとき

1. [共有メモ](../hackathon-memo.md)とヒアリング結果を読み、改善する作業を一つ選ぶ。
2. 専用スキルで、入出力と正常・失敗入力の期待結果を決める。
3. 必要な提供データを確認し、使う公開出典を絞る。原価・工賃・見積条件と、許可された会話記録を中心にする。人口・交通・車両統計は市場背景、天候は予約・入庫状況の振り返りに限定し、整備判断や個別価格の代用にしない。
4. 3人の担当は、画面、処理・データ、ヒアリング・検証・発表を起点に調整する。共通の[tobetsu-mvp](../../.agents/skills/tobetsu-mvp/SKILL.md)に従って接続仕様と統合時刻を合わせる。
5. 実装は[Git協業スキル](../../.agents/skills/github-collaboration/SKILL.md)で担当ファイルを確保する。共通の[スキル一覧](../skills.md)に従い、UIはFigma Design、発表はFigma Slidesを使う。tobetsu-prototype、tobetsu-pitch、frontend-design、webapp-testingを目的に応じて使い、必要な接続・ツールは実作業時に確認する。

## 呼び出し例

```text
$tobetsu-workshop-ops 共有メモのCを候補に、ヒアリング前の暫定MVPと入力・出力を整理してください。引用元リストから必要なデータだけ選び、提供待ちの項目と例示で実演できる範囲を示してください。
```

スキルの一覧更新は利用環境による。ブランチ／作業フォルダーを開き直しても表示されなければ、上のSKILL.mdを明示して読ませる。共通スキルや実行ツールの準備は各端末で確認する。
