# 案A: 標準工数＋状態補正

- 状態: 提案。基準人時・補正値は未取得／未検証
- 共通定義: [体系化計画・入力辞書](README.md)

## 1. 方針

既存ソフト等の基準人時を起点に、現車で確認した状態から追加工程を選び、その人時を加える。ヒアリングで挙がった「基準時間では終わらない」理由を、説明可能な工程に分解して記録する。

「北海道だから一律○倍」「古い車だから一律○倍」という補正は設定せず、錆・固着等の観察と必要な追加作業を対応づける。

## 2. この案で追加する入力

| 項目 | 必須度 | 形式・単位 | 取得先・確認事項 |
|---|---|---|---|
| `standard_ref` 基準データの参照ID・版・確認日 | 算出時必須 | ID、日付 | 利用可能な既存ソフト・資料。対象車両、作業、利用範囲を確認する |
| `base_person_hours` 基準人時 | 算出時必須 | 人時 | 元資料の時間が人時か経過時間かを確認する |
| `base_scope` 基準に含まれる工程・数量 | 算出時必須 | 工程ID、個／組 | 片側か両側か、脱着・調整等を含むかを確認する |
| `observed_condition` 錆・固着・雪氷・損傷等の状態 | 必須、不明可 | 選択値、観察メモ | 整備士による現車確認。未分解の内部状態は未確認とする |
| `extra_operations` 状態に応じた追加工程 | 該当時必須 | 工程ID、根拠、人時の下限／上限 | 整備士の説明・確認済み実績。基準に含まれていない工程を選ぶ |
| `shared_deductions` 同時作業で共有する工程 | 該当時必須 | 工程ID、控除人時、理由 | どの作業から何を控除したかを記録する |
| `rule_version` 追加・控除ルールの版・承認者 | ルール使用時必須 | 版、担当者 | 仮ルールと承認済みルールを区別する |

補正候補の例は、固着した固定部の取り外し、雪下ろし、追加清掃、損傷に伴う追加交換等。必要性と人時は整備士が確認する。作業手順・時間をAIだけで確定しない。

## 3. 算出と不足情報の扱い

`推定人時 = 基準人時 + 基準に含まれない追加工程の人時 − 確認済みの共有工程控除`

- 下限・上限は追加工程の想定条件に対応づける。統計的な信頼区間とは呼ばない。
- 固着等が未確認なら「追加作業の可能性あり・要現車確認」と表示する。未知の補正を0として確定しない。
- 基準が対象仕様に適合しない、時間の定義が不明、補正に根拠がない場合は算出を止め、Cの工程確認または整備士の手動見積もりへ進む。
- 追加工程が基準内にある場合は加算しない。控除は工程と人時が確認できる場合だけ行う。
- 確定人時と時間単価から工賃を算出し、手動修正理由を保存する。

## 4. 実施計画

1. 対象作業を1つ選び、基準時間の単位・数量・含有工程を確認する。
2. その作業で起きる追加工程を整備士に聞き、状態→追加工程→確認方法の対応表を作る。
3. 補正人時は、利用できる実績または整備士の暫定見積もりを出所付きで記録する。未取得なら空欄を維持する。
4. 通常状態、固着あり、状態不明、同時作業ありの入力例で計算・確認フローを比較する。
5. 実作業後に追加工程の人時を記録し、仮ルールと実績の差を見直す。

成果物は「基準データ台帳」「状態別の追加工程表」「入力票」「補正履歴」。採用条件は、整備士が基準・加算・控除を説明できること。

## 5. 表示例（計算説明用の架空値）

| 項目 | 値 |
|---|---|
| 仮の基準人時 | 1.0人時 |
| 固着対応の追加工程 | 0.4〜0.8人時（基準外と仮定） |
| 雪下ろし | 0.2人時（同一見積もりで1回と仮定） |
| 共有工程控除 | なし |
| 推定範囲 | 1.6〜2.0人時 |
| 担当者の確定値 | 1.8人時（修正理由を記録） |

数値は仕組みの説明用。実際の整備時間や補正係数の根拠として使用しない。
