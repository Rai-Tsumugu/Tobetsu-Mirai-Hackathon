# 案B: 類似作業の実績参照

- 状態: 提案。人時付き実績の有無・件数・品質は未確認
- 共通定義: [体系化計画・入力辞書](README.md)

## 1. 方針

車両仕様、作業範囲、現車状態、作業環境が近い過去事例を探し、実作業人時を根拠候補として提示する。記憶や過去金額だけに依存せず、「どの事例と条件が近いか」を見積もり担当者が確認できるようにする。

過去見積もりが保存されているという発言はあるが、実作業人時も保存されているとは確認できていない。まず記録項目を棚卸しする。

## 2. この案で追加する入力・実績記録

| 項目 | 必須度 | 形式・単位 | 取得先・確認事項 |
|---|---|---|---|
| `case_id` 実績ID・実施日 | 参照時必須 | ID、日付 | 許可された作業記録。顧客識別情報を除いた参照用IDを用いる |
| `case_vehicle` 当時の車両仕様 | 参照時必須 | 共通辞書と同じ形式 | 現在の車両情報で過去の仕様・状態を上書きしない |
| `case_job_scope` 作業、部位、数量、含有工程 | 参照時必須 | 作業・工程ID | 今回と同じ作業範囲かを確認する |
| `case_condition` 当時の錆・固着等の状態 | 参照時必須、不明可 | 状態、観察メモ | 未記録の状態は不明。条件比較の不足として示す |
| `actual_person_hours` 実作業人時・計測方法 | 工数候補に必須 | 人時、計測／事後申告等 | 作業者別の実作業時間から集計する |
| `elapsed_and_wait` 経過時間、待機時間、人数 | 条件確認に使用 | 時間、人 | 人時の定義・記録の整合を確認する |
| `extra_and_shared` 追加作業、共通工程の配分 | 該当時必須 | 工程ID、人時、配分方法 | 複数作業まとめて記録した人時を無根拠に割り振らない |
| `case_context` 設備・作業方法・担当者の経験区分 | 任意 | 選択値、補足 | 作業条件の違いを確認する。経験区分の使用は工場に確認する |
| `selected_case_ids` 採用／除外事例と理由 | 算出時必須 | ID、理由 | 類似条件と相違点を担当者が確認する |

請求人時・過去工賃も参考として別保存できるが、実作業人時と区別する。修理費総額だけの記録は工数候補から除外する。

## 3. 事例選択・算出方法の案

1. 作業コード、部位、数量、含有工程で比較対象を絞る。
2. 車両の仕様差が工程に影響しないか確認する。次に錆・固着、設備等を比較する。
3. 「一致する条件」「異なる条件」「未記録の条件」を候補ごとに表示し、担当者が採用／除外する。
4. 採用した比較可能な事例の実作業人時の中央値を参考値とし、件数と最小〜最大の観測値も表示する。観測範囲を今回の上下限保証にしない。
5. 1件ならその事例の人時として表示し、相場・標準とは呼ばない。採用0件なら自動算出せず、A／Cまたは手動見積もりへ進む。

入力条件の不足が大きい場合は事例の一覧提示にとどめ、比較可能だと自動判定しない。過去に時間が長かった事例も、原因を確認せず外れ値として捨てない。

## 4. 実施計画

1. 過去見積もりと作業記録を分けて確認し、人時・状態・作業範囲があるかを棚卸しする。
2. 共通辞書に合わせた実績記録票を作り、実作業人時と請求人時を分けて収集する。
3. まず1作業の事例を整理し、比較に使えるものと不足情報があるものを分ける。
4. 類似事例一覧で条件差と計測方法を表示し、整備士に採用理由を記録してもらう。
5. 新しい見積もり時には、その時点より後の実績を使わずに予測を残す。作業完了後に実測との差・不足条件を記録する。

成果物は「実績入力票」「匿名化した実績一覧」「類似条件の確認表」「採用・除外記録」。採用条件は、条件が追跡できる人時付き実績を整備士が選べること。必要件数や精度基準は実績を見て合意する。

## 5. 表示例（計算説明用の架空値）

同じ作業範囲・比較可能な状態と仮定した3事例が1.5、1.8、2.1人時なら、参考中央値は1.8人時、観測範囲は1.5〜2.1人時、採用件数は3件と表示する。

別の記録に工賃だけがある場合は「実作業人時なし」と表示し、中央値に含めない。例の数値・件数は実績ではない。
