# 当別未来フェス：優先順位付きSkill設計

この設計はチーム共有メモを基にした準備案。イベントの最新案内や事業者本人の回答が得られたら、当日の判断を更新する。

目的は3人で、課題を選び、使える試作を作り、約3分で価値と確認状況を伝えること。新規Skillはこのリポジトリの `.agents/skills/` に配置し、チームが同じ手順を共有できる形にする。

## 優先順位と受け渡し

優先順位は事前に整える順序。発表の骨子はMVP選択後から作り始め、Git協業はファイルを編集する時点で使う。各工程を完全に終えてから次へ進む必要はない。

全Skillの優先順位、入力、成果物、呼び出し例は [Skill一覧](skills.md) に集約している。課題整理からMVP設計、データ処理、UI・試作、発表へ成果物を渡し、各Skillに定めた完了条件で状態を確認する。

既存のGit協業Skillは再利用する。新規5つは指示中心のSkillとし、不要なスクリプト、サービス接続、追加アカウント設定を含めない。表計算・画面実装・発表資料の既存Skillは該当作業で利用可能な場合に使い、ない場合にも設計やローカル処理を進められるようにする。

## Figmaを使う方針

ユーザーの指定により、UIはFigma Design、発表資料はFigma Slidesで作成する。

1. MVPを決め、入力・結果・必要なエラー状態を整理する。
2. Figma Designで編集可能な画面と共通部品を作り、中心の操作を確認する。
3. 対象画面のデザイン情報を取得し、プロジェクトの開発環境に合わせてコードと処理を実装する。
4. 実アプリの見た目と操作・計算結果を確認する。
5. Figma Slidesへ、課題、UI、実演、効果の根拠をまとめる。発表の骨子は開発と並行して用意する。

Figma上の操作プロトタイプと実アプリの動作確認は別に記録する。Figmaは画面・資料の作成に使い、Googleの開発基盤の具体的サービスは引き続き確認する。

利用するFigma Skillは、画面作成でfigma-useとfigma-generate-design、実装でfigma-design-to-code、スライド作成でfigma-useとfigma-use-slides。新しいファイルを作る前にはfigma-create-new-fileを読む。これらは現在のセッションで利用可能だが、Figmaアカウントの接続・対象ファイルの権限・メンバーのアクセスは実際の作成時に確認する。

今回の更新はSkillと進め方の変更。Figmaファイル、UI、発表スライドはまだ作成していない。

## 確認方法

作成時にSkillの形式、名前とフォルダー名、参照先、成果物の受け渡し、境界事例を確認する。形式検証はヒアリングや開発の成功を保証しない。当日の事業者データ、アカウント、実演環境での評価は別途行う。

専用Skillの作成時には、skill-creator付属の形式検証で新規5件が合格し、当時の設計書の相対リンク6件が実在することを確認した。既存のGit協業ファイル5件とAGENTS.mdは作成前後のSHA256が一致した。実データを用いたSkillの実行評価と発表練習は未実施。

初回コミット前の準備では、既存ファイルを含む対象の承認待ちとしてローカルに保存していた。その後、ユーザーからここまでの内容のコミット・プッシュを依頼された。現在の保存・公開状態はGitの履歴とリモートの状態で確認する。
