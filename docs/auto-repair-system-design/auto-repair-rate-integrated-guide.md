# ③時間単価シミュレータ 統合ガイド

このSimulatorは、実工場の単価を自動決定するものではありません。入力した費用・人時・根拠を試算候補として保存し、担当者が内容・有効日・根拠を確認して承認するためのローカル検討画面です。初期値とfixtureはすべて架空です。

## 基本の使い方

既定の統合フォームでは年度費用、期間総労働人時、期間請求可能割合、別請求材料の除外確認、根拠資料日・ID・メモ、有効開始日を一画面で入力します。保存後は共通記録の候補に承認者・理由・有効開始日を入力し、人が承認します。画面上部の段階ボタンはR13費目確認、R16稼働積算、R06利用率シナリオ、R30根拠確認、R19有効日参照を開く案内です。個別画面間で入力値は自動転送されません。別画面を使う場合は、その画面で根拠と値を再入力・再確認してください。通年・冬季などの比較計算はR06/R11等の専用方式で行い、統合フォームの「年度・シナリオ」欄は記録用ラベルです。

候補の金額だけでなく、根拠・不足項目・除外項目・有効日を確認してください。未知額や0分母がある場合は画面が停止状態を示します。材料など別請求項目は労務費から除外して確認します。既承認値を遡及変更せず、新しい候補と承認履歴を追加します。

## 採用した案

R01の年次配賦費用と期間人時の基本計算を共通契約にし、R06の稼働率条件比較、R07–R10の配賦・暖房・冬季・平滑化、R11–R14の季節・イベント・簡単入力・CSV確認、R15–R18の年額・稼働・家族労務・不明費用、R19–R30の有効日・内部原価・カテゴリ・承認履歴・シナリオ・根拠確認を個別画面として提供します。

| 統合フォーム上の段階 | 採用した案 | 画面で行うこと |
| --- | --- | --- |
| 年度費用・期間稼働 | R01, R13, R15, R16 | 合算費用、人時、`u_period` を入力し、分母を計算 |
| 条件比較 | R06, R11, R28 | 低・標準・高 `u_period` をサーバーで比較し、冬季等は専用画面で確認 |
| 根拠・除外 | R14, R18, R30 | 材料除外を確認し、出典・日付・メモ・不確実性を保存 |
| 人の承認 | R25 | 候補値・有効日・承認者・理由を共通履歴へ記録 |
| 有効単価参照 | R19 | 指定日時点の工場標準顧客単価を確認 |

共通期間単価は `rate = allocable_cost_yen / (period_total_person_hours * u_period)` です。案件時間の `job_billable_ratio` は期間分母に混ぜず、総人時基準の案件時間に限り一度だけ適用します。期間請求人時と案件請求人時の方式別入力は `RateProposal.period_total_person_hours`, `u_period`, `job_person_hours`, `hours_basis` に対応します。内部単価やカテゴリ・冬季スコープは工場標準顧客単価と別履歴にします。

## 制限と確認事項

- 外部データや会計APIは取得しません。CSVを使う場合はローカル入力を人が確認します。
- デモ値は実績・相場・賃金の助言ではありません。実工場データが未提供の部分は未確認のままです。
- 年間・冬季の比較、CSV税区分、材料除外、費目配賦、家族労務の仮原価などは人が資料に基づき判断します。
- 方式固有の画面とAPIには確認段階の試作があります。画面・API・個別受入テストが未検証の案は、運用に使える完成機能とみなさず、利用前に個別確認してください。
- SQLite履歴はこのローカルSimulator用です。バックアップ、複数利用者認証、権限管理、実運用の監査基盤は含みません。
