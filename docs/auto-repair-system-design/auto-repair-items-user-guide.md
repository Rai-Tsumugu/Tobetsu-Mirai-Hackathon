# 部品・材料価格マスタ：統合版の使い方と特徴

## 目的と構成

材料の価格登録、CSVからの取込、見積への単価固定、実使用量の記録を、一つのローカルアプリで扱います。30案の共通データ形式を使い、確認者・変更理由・価格版を追跡できるようにしています。

- 実装：[src/auto_repair_items](../../src/auto_repair_items/)
- 統合処理：[integrated.py](../../src/auto_repair_items/integrated.py)
- 統合画面：[workspace.html](../../src/auto_repair_items/workspace.html)
- 元の設計：[30案の設計資料](auto-repair-items-ideas-30.md)

統合画面の基本操作と、30案の詳細操作は分かれています。配合・掛率・端数処理などは個別機能を使用します。すべての機能が一度の見積保存で自動適用される構成ではありません。

## 起動方法

Python 3を使用します。外部パッケージのインストールは不要です。リポジトリのルートで実行します。

```sh
PYTHONPATH=src python3 -m auto_repair_items.app --port 8765 --db /tmp/auto_repair_items.sqlite3
```

ブラウザで http://127.0.0.1:8765 を開きます。ポートが使用中なら `--port 8766` に変更し、URLも変更してください。終了は実行したターミナルで `Ctrl+C` を押します。

SQLiteファイルにデータを保存します。同じ `--db` のパスで再起動すると保存内容を引き継ぎます。`/tmp` はOSの清掃などで消える可能性があるため、継続利用する検証データは、存在する任意の保存フォルダ内のパスを指定してください。初回起動時に架空の塗料価格が登録されます。

## 統合画面の操作

### 1. 確認状況を見る

「確認状況」で材料と価格区分、単価、仕入先、有効期限を確認します。確認日不明・未承認・有効期間外などは要確認として表示します。保存済み見積は一覧のボタンから再表示できます。

表示対象は適用日までに有効開始した承認済み価格を基準に選びます。最新版が期限切れの場合、古い価格を自動で採用せず、期限切れを示します。人が確認した日と価格の更新日は別の情報です。

### 2. 材料と価格を登録する

「材料・価格登録」で以下を入力します。

| 項目 | 意味・注意 |
|---|---|
| 材料ID | 同じ材料を識別する固定ID |
| 材料名・分類・単位 | 同じIDで名称・分類・単位を変更すると拒否されます |
| 単価 | 0以上の数値。未確認の価格を0として入力しないでください |
| 価格区分 | 仕入／販売。見積作成には販売価格を使用します |
| 出所・価格更新日 | 価格の根拠と更新日 |
| 人が確認した日 | 価格を人が確認した日 |
| 仕入先ID | 新規では任意。更新時に空欄なら一意の既存仕入先を引き継ぎます。複数ある場合は指定が必要です |
| 有効開始日・終了日 | 新規の終了日空欄は期限なし。更新時の空欄は既存終了日を引き継ぎます |
| 取引条件 | JSON形式。空欄は既存条件を引き継ぎ、入力した項目だけ変更します |
| 確認者・理由 | 誰が、なぜ登録・変更したか |

取引条件の例：

```json
{"currency":"JPY","freight_basis":"included"}
```

「確認して価格版を保存」で登録します。価格変更も同じ材料IDと価格区分で登録します。旧価格は上書きされず、新しい版が追加されます。仕入価格を登録しても販売価格は自動では作られません。

### 3. CSVの候補を確認・承認する

「CSV取込」でファイルを選ぶか、本文を貼り付けます。統合画面では次の列名を使用します。

```csv
item_id,name,category,unit,unit_price,price_type,source,updated_at
sample-paint,架空の塗料,塗料,ml,120,販売,架空の確認資料,2026-10-11
```

1. 出所を入力して「候補を読み込む」を押します。
2. 読取結果を確認し、登録する行のチェックボックスを選びます。
3. 確認者を入力し「選択した候補を承認して登録」を押します。

読取だけでは価格マスタに登録しません。不正な行は承認対象から外れます。別の取込バッチの候補を混ぜた承認は拒否されます。列名の対応づけが必要なCSVは個別機能M09またはAPIを使用してください。

### 4. 見積の価格を固定する

「見積作成・再表示」で見積ID、価格適用日、確認者を入力します。各行に材料ID・数量・単位・必要に応じた仕入先IDを指定し、複数材料は「材料を追加」で増やします。

「単価を固定して保存」を押すと、その適用日の承認済み販売価格、価格版、条件、数量を保存します。価格未登録・期限切れ・単位不一致・仕入先が曖昧な場合は停止します。同じ見積IDの再保存は拒否されるので、改訂見積は別IDで保存してください。

例：単価120円/ml、数量2.5mlなら、税・端数処理前の行金額は300円です。後から単価を130円/mlに変更しても、保存済み見積は120円/mlのまま再表示されます。

**統合画面の小計には税・M29の端数処理を自動適用しません。** M29で算出した結果を、統合見積へ自動で合流する処理もありません。

### 5. 実使用量を記録する

保存した見積の見積IDと見積行IDを使い、「実使用量」で実際の数量・確認者・差分理由を入力します。見積表示時には先頭行のIDが入力欄に引き継がれます。他の行を記録する場合は行IDを変更してください。

差分は「実使用量 − 見積量」です。見積2.5ml・実績2.25mlなら差分は−0.25mlです。実績を保存しても、見積数量・価格・標準使用量は変更しません。

## 30案の特徴

「30案の個別機能」から `/ideas` の画面へ移動します。画面の既定値は架空の検証例です。一部の操作は複数段階のAPI入力が必要で、画面から全操作を完結できるとは限りません。

| ID | 機能 | 特徴 |
|---|---|---|
| M01 | 塗料コード正規化 | 表記揺れを整理し、原表記も保持 |
| M02 | 容量・入数単位変換 | 根拠を確認した換算率で基準単位へ変換 |
| M03 | 仕入・販売価格 | 価格区分を独立して保存・参照 |
| M04 | 仕入先別価格 | 送料・税・納期などの一致条件で比較 |
| M05 | 塗料配合マスタ | 配合比率と版を管理し、原価候補を計算 |
| M06 | 価格イベント台帳 | 変更理由・出所・担当者を追記記録 |
| M07 | 単品価格入力 | 1品目ずつ登録し、確認済み価格を検索 |
| M08 | クイック価格変更 | 差分確認後に新価格版を追加 |
| M09 | CSV列対応 | 列の対応づけと行単位の確認・承認 |
| M10 | Excel取込 | 固定8列・単一シートのXLSXを読取 |
| M11 | PDF領域指定 | 指定領域の架空明細候補を確認する模擬機能 |
| M12 | OCR確認 | 架空読取候補を項目ごとに人が確定 |
| M13 | 卸JSON | 利用条件・品番対応を確認したローカルJSON取込 |
| M14 | 確認経過表示 | 人の確認日と出所更新日を区別 |
| M15 | 有効期限 | 期限なし・未確認・期限切れを区別 |
| M16 | 更新待ち隊列 | 期限切れ・未確認・差分を優先順位付きで表示 |
| M17 | 更新差分確認 | 同条件の候補について差額と採否を記録 |
| M18 | 条件付き価格 | 数量・期間などに合う特別価格候補を提示 |
| M19 | 部位別材料辞書 | 部位と仕上げから材料候補を提示 |
| M20 | 面積帯の使用量 | 承認済みの使用量幅と金額幅を提示 |
| M21 | 配合の比例計算 | 必要量から材料ごとの数量・金額を計算 |
| M22 | 工程別材料候補 | 工程から材料を提案し、人が数量を確定 |
| M23 | 見積量と実績 | 使用量の差分と理由を別記録 |
| M24 | 価格履歴 | 同じ取引条件の価格版を時系列で表示 |
| M25 | 原料指数 | 出所・利用条件付きの参考表示。価格に自動反映しない |
| M26 | 粗利影響 | 仕入・販売価格の変化による粗利差を試算 |
| M27 | 見積差分 | 前回見積と現在の同条件価格を比較 |
| M28 | 掛率管理 | 適用日・仕入先・分類別の掛率を版管理 |
| M29 | 端数処理 | 行・税区分ごとの丸め規則と計算根拠を記録 |
| M30 | 価格スナップショット | 見積時点の単価・数量・条件を固定 |

## 共通データとAPI

品目の共通8項目は次のとおりです。変数名は `snake_case` に統一しています。

`item_id`, `name`, `category`, `unit`, `unit_price`, `price_type`, `source`, `updated_at`

分類は `部品`・`塗料`・`溶剤`・`消耗品`、価格区分は `仕入`・`販売` です。金額と数量はDecimalで計算し、JSON・SQLiteでは十進文字列として扱います。見積と価格履歴は価格版IDで追跡します。

| エンドポイント | 用途 |
|---|---|
| `POST /api/workspace` | 統合操作 |
| `POST /api/ideas/M01` ～ `M30` | 個別機能の操作 |
| `GET /api/ideas` | 各案の名称・説明・既定入力 |
| `GET /api/prices` | 保存済み価格版 |

統合操作の `action` は `dashboard`、`register`、`update_price`、`stage_csv`、`approve_import`、`save_quote`、`get_quote`、`record_usage`、`tool` です。`tool` は対応する個別機能へ明示的に処理を委譲します。詳細な入力は [integrated.py](../../src/auto_repair_items/integrated.py) と [連携テスト](../../src/auto_repair_items/tests/test_integrated.py) を参照してください。

## 実装・検証の範囲

- CSVと制約付きXLSXは実際のローカル読取に対応します。
- PDF抽出・OCR画像認識は未接続の模擬機能です。卸APIや外部システムにも接続していません。
- 例示価格・配合・使用量・指数は架空値です。実際の工場標準や塗装レシピとして検証していません。
- 127.0.0.1限定の検証サーバーです。ユーザー認証、正式帳票、本番運用は未実装です。
- 統合版はLunaによる独立確認とブラウザ操作確認を実施しました。各30案それぞれの二重チェックは未完了です。
- 統合版実装時点でテスト195件が通過しました。再実行する場合は以下を使用します。

```sh
PYTHONPATH=src python3 -m unittest discover -s src/auto_repair_items/tests -v
```
